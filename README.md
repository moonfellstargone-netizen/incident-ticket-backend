# 故障工单与知识检索后端系统

基于 Flask 和 SQLite 的个人学习项目，围绕故障工单业务、自动化验证和知识检索逐步推进。业务使用手工录入的模拟故障，后续检索使用自行编写的示例文档。

**当前处于方案阶段，尚无可运行的业务代码、应用测试结果或已实现的知识检索功能。**

## 已确认的首版范围

- 创建工单，查询列表与详情，更新状态并记录处理结果。
- 提单人只查看自己的工单；处理人查看和处理全部工单，暂不做派单。
- 状态只允许“待处理 → 处理中 → 已解决”单向流转。
- 解决工单必须填写非空白的处理结果；状态、处理结果和解决人需要在同一次操作中完整保存。
- 包含必要的身份与权限校验、参数校验、错误返回、日志和基础测试。
- 首版以本地接口演示为主，不建设复杂前端。

## 待确认的实现细节

- Python 原生 sqlite3、pytest 的具体使用方式。
- 预置账号、登录会话及 CSRF 保护的交互方案。
- API 路径、字段限制、错误格式和状态码等接口契约。
- 用户表与工单表的字段、约束及测试数据准备方式。

## 阶段与验收计划

1. 业务后端与基础测试：演示完整工单流程；验证错误输入、越权与非法状态流转得到拒绝，且没有错误写入数据。保留代码、启动说明、测试方法、演示材料和已知限制。
2. 自动化验证完善：覆盖数据准备与清理、用例隔离、数据库异常、缺陷复现与回归。记录一个完整的问题排查案例，基础稳定后再评估持续集成。
3. 小型知识检索：导入自编故障文档，检索相关内容并生成带来源的辅助回答。准备固定的可回答问题、无答案问题和来源核对样例，按实际结果记录限制。

## 开发与资料边界

- 每项能力以实际实现和可复现的验证为依据，不将计划写成已完成成果。
- 使用自编资料和模拟数据；不上传原单位代码、内部文档或敏感信息。
- 模拟故障如实标注；性能数据仅在真实测量并记录环境与方法后发布。
- AI 可以辅助开发，关键实现需要能够解释，并通过独立的小改动与验证确认理解。
- 本次仅初始化仓库和项目说明；业务代码在后续确认开发阶段后逐步实现。

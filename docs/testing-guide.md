# 测试设计

测试使用模拟账号、工单和故障文档，最新结果见[验证记录](verification.md)，运行命令见 [README](../README.md)。

## 用例范围

- 业务流程：创建、查询、筛选、分页、状态推进、处理结果与历史。
- 权限：未登录、角色限制、跨用户访问；同时核对列表条目和总数。
- 输入：空值、长度边界、错误类型、非法编码、未知字段及重复参数。
- 写入一致性：拒绝更新后整行不变，工单与历史一起提交或回滚。
- 知识与模型：文档导入、更新引用、来源核对、无答案、提供方错误和调用额度。

写接口同时断言响应和数据库内容。正常返回需确认写入持久化；拒绝或失败需确认没有部分修改。

## 数据隔离

[conftest.py](../tests/conftest.py) 为每个用例创建独立 SQLite 文件并准备三个账号。客户端实际获取 CSRF、登录并保留各自 Cookie 会话；测试不依赖开发库或其他用例先执行。配置检查拒绝使用默认开发数据库。

## 重点场景

- [状态与并发](../tests/test_ticket_workflow.py)：两个处理人通过线程屏障读到同一旧状态，预期一个成功、一个409，结果与解决人属于成功请求。
- [提交失败](../tests/test_commit_failure.py)：触发器及延迟外键让 UPDATE 成功、COMMIT 失败，确认业务、历史和附带写入回滚，移除故障后恢复。
- [请求日志](../tests/test_observability.py)：响应与日志共享请求编号，敏感请求内容不进入日志。
- [模型异常](../tests/test_model_answer.py)：模拟超时、HTTP 中断、错误引用和资料变化；检查错误返回、预算记录及无重试。
- [验收入口](../tests/test_model_check.py)：使用模拟传输确认套件能拒绝错误来源，且无答案不调用、失败即停止。

故障注入发生在独立测试库，不属于生产事故；竞争更新用例验证指定条件，不是性能测试。

## 演示与回归

Flask 测试客户端用于自动化回归，`scripts/demo_workflow.py` 另启本机临时服务，以真实 HTTP 验证完整流程和重启持久化。

pytest 不调用外部模型。真实模型检查由 `scripts/check_model.py --live` 显式执行并可能计费，方法见[模型配置](knowledge.md)。缺陷的现象、原因、修复与回归见[排查记录](troubleshooting.md)。

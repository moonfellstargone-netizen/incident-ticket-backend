# AI 辅助开发与检查记录

这是个人求职项目的协作记录。用户提供目标、已有基础和范围约束，并确认使用 Flask、SQLite；AI 辅助实现代码、测试和文档，并通过工具运行验证。未使用企业代码、真实工单或客户资料。

提供的岗位材料包含对 AI 辅助开发、代码理解、测试验证和问题记录的要求。本文记录实际选择和证据，不判断这些岗位目前是否仍招聘，也不以 AI 产出替代本人能力证明。

## 已采用的实现和检查方式

- **保留 Flask 和 SQLite。**围绕单个工单流程完成业务、权限、事务和测试；没有因功能增加而切换语言或同时学习多个 Web 框架。实现见 [tickets.py](../ticket_backend/tickets.py)、[db.py](../ticket_backend/db.py)。SQLite 经验不能表述成已熟练使用 MySQL。
- **权限和 CSRF 都实际检查。**身份从会话取出，角色重新从数据库读取，创建人和解决人由服务端确定；写接口校验令牌，登录后更换令牌。检查见 [test_auth.py](../tests/test_auth.py) 和 [test_tickets.py](../tests/test_tickets.py)，不能只因为请求中出现令牌就认定防护有效。
- **事务完成后才报告成功。**状态、处理结果和解决人一起保存；条件更新防止覆盖已经变化的状态。除正常流程，还用真实 SQLite 触发器和延迟约束验证语句失败、提交失败、回滚及移除故障后的恢复，见 [test_ticket_workflow.py](../tests/test_ticket_workflow.py) 和 [test_commit_failure.py](../tests/test_commit_failure.py)。
- **补充输入检查。**JSON 对象要求明确字段，拒绝错误类型、额外字段、NUL、非法 Unicode 和过深嵌套；编号先检查字符串再转整数。实现见 [validation.py](../ticket_backend/validation.py)，对应测试同时检查响应和没有意外写入。
- **留下可重复验证。**使用独立测试库、真实登录和 Cookie 会话，保留自动化回归与本机 HTTP 演示；验证环境、方法、结果和已知限制集中在[验证记录](verification.md)，不从测试数量推导熟练程度或生产可用性。

本轮知识检索与模型扩展已执行来源原文、行号、校验值、无答案、引用与预算检查，最新纳入334项完整回归。6篇模拟资料由 AI 辅助撰写，待本人复核；固定18题先发现一条自然问法漏检，分析后补充通用疑问词规范化并增加不同问法与未知主题回归，保留阈值不变。该集合已用于开发调整，不能包装为独立准确率。模型异常路径使用模拟传输，另执行4次真实调用和6题固定样例检查；来源编号有效不能证明每句话都有依据，不称为可靠知识库验收。

## 一个实际发现并修复的问题

超长编号案例来自本项目本地开发时的验证，不是生产事故，也不声称由用户本人独立发现或修复。

1. 初版采用整数路由，正常编号可用，但5000位数字在路由转换阶段触发异常，视图中的数据库范围检查无法接住。
2. 定位后采用字符串路由，先限制长度、ASCII 数字格式和正整数64位范围，再执行转换和查询；没有通过扩大解释器限制掩盖问题。
3. 保留 `test_ticket_path_beyond_python_integer_digit_limit_returns_404`，并回归正常读取、编号边界和归属权限。

详细复现、原因和用例入口见[排查案例](troubleshooting.md)。这体现了对 AI 初版产出的验证与修正；不能据此改写成学习者亲手完成的排障经历。

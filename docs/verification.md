# 第一个开发小步的验证记录

验证日期：2026年10月18日。范围是预置账号登录、创建工单、查询详情及相应错误处理。

## 环境与方法

- Windows，Python 3.13.9，SQLite 3.51.0。
- Flask 3.1.2，Werkzeug 3.1.3，pytest 8.4.2。
- 使用已有 Anaconda 解释器，没有安装依赖或修改全局环境。
- 自动化通过 Flask 测试客户端调用真实业务代码和独立临时 SQLite 数据库，每个测试重新准备数据与客户端会话。
- 当前默认 pytest 临时根目录存在权限问题，改用项目内新建的随机临时目录；未修改系统权限。

## 自动化结果

最终结果：`73 passed in 6.50s`。耗时是本次测试执行记录，不是接口性能数据。

已验证正常创建与持久化、标题和描述边界、错误类型与编码、未知字段、未登录访问、两个提单人之间的访问隔离、处理人只读、CSRF 实际校验与登录后令牌轮换、退出登录，以及错误凭据的统一返回。

数据库写入失败通过临时测试库中的触发器注入：请求返回通用500、后台留错误日志、前端响应不含内部 SQL 或数据库路径、工单数量不增加；移除触发器后，同一业务操作成功。这是模拟故障验证。

命令级回归实际调用 `init-db` 和 `seed-demo`，验证建表、密码哈希和重复执行时的数据保留。另覆盖超长工单编号与深层 JSON 的开发缺陷回归。

## 真实 HTTP 检查

在本机回环地址启动临时服务，通过 HTTP 和独立 Cookie 会话完成以下检查：

- 获取令牌、登录、创建工单、查询详情成功。
- 另一个提单人读取该工单返回404，处理人可以读取。
- 空白标题返回400，缺少 CSRF 令牌返回403。
- 退出后查询返回401。
- 重新建立应用、重新打开同一数据库后，原工单仍然存在。

检查结束后服务已关闭，临时验证未使用开发数据库。

# Markdown 导入 UnicodeDecodeError：文件编码不是 UTF-8

资料性质：个人项目自编模拟资料导入故障，所有文本均为公开可演示的虚构样例。

## 现象与适用范围

模拟知识文档采用 GBK 编码保存，按 UTF-8 严格读取时出现 UnicodeDecodeError，整个导入批次被拒绝。文档必须是顶层 Markdown 文件，有 `# ` 开头的标题，且正文不得包含 NUL 字符。

## 核对步骤

用编辑器核对实际文件编码，确认不是只修改了文件后缀。检查文档是否含二进制内容、NUL 字符、过长单行或意外导入的非演示材料。文件名使用 ASCII 字母数字、下划线和连字符。

## 模拟处理与回归

保留原样例，将演示文本以 UTF-8 重新保存；重新导入后核对文档标题、原文、SHA256 校验值和来源行号。重复导入相同字节应标记 unchanged，不新增文档和分块。修改内容后再次导入应更新原文并分配新的 chunk_id，让旧引用失效。

## 限制

本例不自动猜测编码、不从办公文档或 PDF 抽取文本，也不导入子目录。

# SQLite SQLITE_BUSY：写事务锁未释放

资料性质：个人项目自编模拟故障，仅用于检索与回归样例，未发生于真实生产环境。

## 现象与适用范围

模拟两个独立 SQLite 连接访问同一文件，第一个连接开启写事务但没有提交；第二个连接写入时等待超时，报告 `sqlite3.OperationalError: database is locked` 或 SQLITE_BUSY。

## 核对步骤

检查是否存在过长的写事务、异常分支遗漏 rollback、请求结束未关闭连接，以及其他演示进程是否持有事务。核对操作的确是同一个数据库文件，避免误把路径错误当成锁问题。

## 模拟处理与回归

先让持锁事务正常 commit 或 rollback，再重试第二个连接。保持写事务尽量短，用连接上下文统一提交和回滚，并在请求结束关闭连接。增加等待时间不能替代释放写锁。不要删除正在使用的数据库文件或 SQLite 伴随文件。

## 验证与限制

复现前记录两条连接的事务顺序，释放写锁后确认原操作成功且数据没有重复写入。本例没有覆盖数据库备份恢复、文件损坏修复或分布式数据库。
